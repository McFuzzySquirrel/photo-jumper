# Problem / Intent
Fix BUG-001: infinite loop in `js/detection/helpers.js` `addHelpers()` function. Discovered during Android emulator testing — after photo selection and ML detection, the game hangs at `addHelperPlatformsIfNeeded()` because `addHelpers()` returns `candidates.length > 0` instead of tracking actual placement success. When candidates fail `canReachPlatform`/`isWithinBounds`, `failedAttempts` never increments, causing an infinite loop. Also fix Android native UX issues found during emulator testing (splash overflow, blank screen after splash, photo selection flow).

# Decisions Made
- Decision: Use 3-tier letter placement with relaxed fallback
  - Reason: Strict filtering (exclude start, goal, ceiling-blocked) leaves zero platforms in low-platform ML scenarios
  - Impact: Letters now appear even with only 7 ML detections; goal platform can host letters at edges
- Decision: Hide debug/detection UI in native mode rather than repositioning
  - Reason: Debug toggles and detection badges are development tools, not needed in production native builds
  - Impact: Clean native UI without affecting web development workflow
- Decision: MAX_ITERATIONS=50 hard cap on helper platform loop
  - Reason: Prevents infinite loop even if logic bugs remain; 50 iterations is generous enough for any real level
  - Impact: Game always terminates helper generation, worst case produces suboptimal but playable level

# Key Learnings
- **Technical**: `addHelpers()` return value must reflect actual placement success, not candidate existence. Boolean semantics matter in loop termination.
- **Technical**: Letter placement needs graceful degradation — strict filtering works for rich levels but fails with few platforms.
- **Technical**: Android Capacitor WebView loads local ONNX model when CDN fails — the `models/` directory is bundled as app assets.
- **Prompting**: Including logcat evidence and exact log messages in agent prompts leads to faster, more accurate fixes.
- **Tooling**: `adb logcat | grep Capacitor/Console` is the primary debugging tool for Android WebView apps.

# If Repeating This Work
- Do: Test with minimal platform scenarios (≤5 platforms) early — this catches letter placement failures
- Do: Include MAX_ITERATIONS caps on any while loop that depends on external function return values
- Avoid: Trusting array.length > 0 as a proxy for "something was accomplished"
- Watch out for: CSS specificity wars between inline JS styles and CSS rules — use `!important` in native overrides

# Future Agent Guidance
- Prefer: Hard caps on all iterative algorithms (while loops, recursive helpers)
- Prefer: Graceful degradation over strict filtering — reduce content rather than show nothing
- Avoid: Using `display: none` without `!important` when JS sets inline styles on the same element
