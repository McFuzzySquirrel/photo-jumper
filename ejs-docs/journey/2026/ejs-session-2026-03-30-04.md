# Key Learnings

**Technical insights:**
- New platform kinds (ml-seg) need to be added to ALL pipeline kind-checks — 5 separate locations in main.js were missed
- Express 5 is a clean upgrade for simple static+API servers — no migration needed
- Vitest works perfectly with vanilla ES modules and no build step (517ms for 165 tests)
- YOLOv8-seg output format: output0 [1,116,N] for detections+mask coefficients, output1 [1,32,160,160] for prototype masks

**Prompting insights:**
- Giving agents explicit "do NOT modify" boundaries prevents scope creep across agent domains
- Including file paths and PRD section references in agent prompts yields precise, focused outputs
- All 6 specialist agents delivered successfully on first call — comprehensive prompts eliminate re-calls

**Tooling insights:**
- Parallel background agent dispatch works well for independent tasks (QA + architect)
- explore agent is valuable for pre-flight surveys before committing to an execution plan
- EJS journey tracking should be initialized at session start, not retroactively  

# If Repeating This Work

**Do this:**
- Survey existing code before assuming PRD gap descriptions are current
- Dispatch independent tasks in parallel (saves significant wall-clock time)
- Initialize EJS tracking immediately at session start
- Use explore agents for reconnaissance before calling specialist agents
- Commit after each task for clean rollback boundaries

**Avoid this:**
- Don't assume PRD "placeholder" descriptions are accurate — verify first
- Don't run all Phase 4 tasks sequentially when some are independent
- Don't skip pipeline validation after adding new platform kinds

**Watch out for:**
- New platform kinds need kind-checks in 5+ locations in main.js (goal filter, spawn cleanup, alt-path helpers, letter placement, clone)
- helpers.js addHelpers() has an infinite loop bug for extreme gaps (BUG-001)
- Service worker cache version must be bumped when assets change  

# Future Agent Guidance

**Prefer:**
- Comprehensive prompts with file paths, PRD sections, and explicit constraints
- Pre-flight exploration before specialist dispatch
- Parallel execution for independent tasks
- Incremental commits after each task completion
- Explicit kind-check audits when adding new platform types

**Avoid:**
- Assuming documentation matches runtime — always verify against source code
- Calling multiple agents that modify the same files simultaneously
- Skipping pipeline validation after detection changes
